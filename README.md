# AirLLM Go

Нативный Go-форк AirLLM для локальной работы с большими языковыми моделями на компьютерах с ограниченным объёмом памяти. Проект развивается в ветке `go-port` и использует исходные файлы весов `safetensors`: они читаются по мере необходимости, без обязательной загрузки всей модели в ОЗУ или видеопамять.

## Цель

Сделать инференс больших моделей предсказуемым на обычном оборудовании за счёт послойной обработки весов, явных лимитов памяти и минимального числа внешних зависимостей. Конечная цель — самодостаточный инструмент, который не требует установленного Python-окружения.

## Текущий статус

Проект находится в активной разработке. Сейчас доступны:

- определение процессора, объёма ОЗУ, графического процессора и доступных бэкендов;
- расчёт потребления памяти с учётом самого большого слоя, KV-кэша и рабочей области;
- чтение конфигураций моделей семейств Llama и Mistral;
- загрузка моделей с Hugging Face Hub в локальный кэш;
- просмотр отдельных файлов `safetensors` и моделей, разбитых на несколько файлов;
- потоковое чтение весов по мере необходимости;
- послойная генерация текста с потоковым выводом токенов.

**CPU reference inference работает, но предназначен прежде всего для проверки корректности и выполняется медленно.** Команда `airllm run` и настольное приложение используют только процессор и не загружают всю модель в память целиком. Поддержка MLX/Metal находится в разработке.

## Установка из исходников

Требуется Go версии, указанной в `go.mod`, Git и C-компилятор для графической библиотеки Fyne.

```sh
git clone https://github.com/lutikk/airllm.git
cd airllm
git checkout go-port
go build -o bin/airllm ./cmd/airllm
```

После сборки исполняемый файл находится в `bin/airllm`. Для проверки установки выполните:

```sh
./bin/airllm help
```

## Настольное приложение

Русский GUI на Fyne использует тёмную тему Slate Indigo и две рабочие зоны: настройки слева, запрос и потоковый результат справа. Приложение принимает ID репозитория Hugging Face в формате `org/repo`, ссылку на модель Ollama или локальный каталог модели, показывает оборудование, лимит памяти и прогресс. По умолчанию выбраны `TinyLlama/TinyLlama-1.1B-Chat-v1.0`, 4 ГиБ памяти, контекст 2048 и 64 новых токена. Отдельная кнопка «Загрузить» получает модель до генерации; «Запустить» и «Загрузить» блокируются во время активной операции. Кнопка «Отмена» останавливает загрузку, конвертацию или генерацию.

Для Hugging Face выберите источник `Hugging Face`, введите `org/repo` и нажмите «Загрузить». Для Ollama выберите источник `Ollama`, введите например `tinyllama:latest` и нажмите «Загрузить». GGUF скачивается напрямую из Ollama registry в `КАТАЛОГ/ollama/<безопасная-ссылка>` без установленной Ollama, daemon или обращения к Ollama API. Затем модель конвертируется в подкаталог `airllm`, и его локальный путь автоматически подставляется в поле модели для запуска нашим engine.

Конвертер GGUF поддерживает Llama-тензоры `F32`, `F16`, `Q8_0` и `Q4_0`; результат сохраняется как `config.json`, `tokenizer.json` и `model.safetensors` в F16. Другие квантования пока не поддерживаются и вызывают ошибку конвертации. Во время скачивания отображаются текущий файл и МиБ скачано/всего; если сервер не сообщил общий размер, показывается только статус и число скачанных МиБ.

Кнопка «Выбрать» рядом с полем «Каталог для загрузки моделей» открывает системный выбор папки. По умолчанию используется `os.UserCacheDir()/airllm/models`; выбранный путь сохраняется в Fyne Preferences, применяется при последующих загрузках из Hugging Face и сопровождается показателем свободного места на диске. Локальная папка модели читается напрямую и не копируется в каталог загрузки.

Раздел «Как получить модель» содержит русскую справку о странице модели на huggingface.co, доступе к gated-репозиториям через `HF_TOKEN` и необходимых файлах `config.json`, `tokenizer.json` и `safetensors`. Для модели из нескольких частей нужны все веса и `model.safetensors.index.json`, если он есть в репозитории. Перед загрузкой проверьте её размер: крупные модели могут занимать десятки или сотни гигабайтов, поэтому заранее выберите диск с достаточным запасом места.

```sh
go build -o bin/airllm-desktop ./cmd/airllm-desktop
./bin/airllm-desktop
```

На macOS автономный пакет приложения собирается без Python:

```sh
./scripts/package_app.sh
open dist/AirLLM.app
```

Скрипт помещает Go-бинарный файл и `Info.plist` в `dist/AirLLM.app`. Используются только системные графические библиотеки macOS.

На Linux и Windows приложение собирается обычным `go build` и не требует Python:

```sh
# Linux (нужны C-компилятор и системные заголовки OpenGL/X11 для Fyne)
go build -o airllm-desktop ./cmd/airllm-desktop

# Windows (в терминале Go на Windows)
go build -ldflags="-H=windowsgui" -o airllm-desktop.exe ./cmd/airllm-desktop
```

Fyne использует CGO и системные графические библиотеки, поэтому переносимость одного бинарного файла зависит от ОС; внешняя среда выполнения Python не нужна. GUI, как и CLI, сейчас выполняет только медленный CPU reference inference — Metal ещё не используется.

## Команды

### `run`: генерация текста на CPU

Запускает послойный инференс модели Llama или Mistral и выводит каждый декодированный токен по мере генерации, пропуская специальные токены:

```sh
./bin/airllm run \
  --model TinyLlama/TinyLlama-1.1B-Chat-v1.0 \
  --prompt "Напиши короткое приветствие" \
  --tokens=32 \
  --context=2048 \
  --memory=4GiB
```

В `--model` можно передать ID репозитория Hugging Face или путь к локальному каталогу модели. Файлы из Hub сохраняются в `os.UserCacheDir()/airllm/models` и повторно используются при следующих запусках. Для локальной модели нужны `config.json`, `tokenizer.json` и веса `safetensors`.

Перед открытием runtime команда рассчитывает память для Float32 CPU reference, включая резидентные веса, самый большой слой, KV-кэш и рабочую область 256 МиБ. Если `--memory` недостаточно, выводится русская ошибка с рекомендацией уменьшить `--context` или увеличить лимит.

Это медленная эталонная реализация на CPU, а не Metal-инференс. Большие модели могут генерировать текст очень долго.

### `doctor`: диагностика системы

Показывает операционную систему, архитектуру, процессор, объём ОЗУ, графический процессор и доступность бэкендов Metal и CUDA.

```sh
./bin/airllm doctor
```

Для машиночитаемого вывода используйте JSON:

```sh
./bin/airllm doctor --json
```

### `memory`: расчёт лимита памяти

Оценивает минимально необходимую память устройства для заданной конфигурации. Команда учитывает самый большой слой, KV-кэш, временную рабочую область и дополнительный буфер предзагрузки.

```sh
./bin/airllm memory \
  --limit=4GiB \
  --layers=22 \
  --context=2048 \
  --kv-heads=4 \
  --head-dim=64
```

Дополнительные параметры:

- `--max-layer` — размер самого большого слоя в байтах;
- `--workspace` — размер временной рабочей области в байтах;
- `--prefetch=false` — не резервировать второй буфер для предзагрузки следующего слоя.

Если выбранный лимит недостаточен, команда сообщает об этом и предлагает способы снизить потребление памяти.

### `inspect`: проверка модели

Для каталога модели команда читает `config.json` и индекс весов, выводит архитектуру и параметры слоёв, а затем проверяет план памяти:

```sh
./bin/airllm inspect /путь/к/модели --context=2048 --limit=4GiB
```

Для отдельного файла `safetensors` выводится список тензоров, их типы, формы и общий объём:

```sh
./bin/airllm inspect /путь/к/model.safetensors
```

Команда не преобразует модель и не загружает все её веса в память.

## Потоковая обработка и лимиты памяти

Основная идея AirLLM — обрабатывать модель последовательно, по слоям. Вместо размещения всех весов на устройстве среда читает нужную группу весов из исходных файлов `safetensors`, использует её и переходит к следующей. Предзагрузка позволяет подготовить следующий слой во время вычислений, но требует дополнительного буфера.

Поэтому необходимый объём памяти зависит прежде всего от самого большого слоя, а не от полного размера модели. В расчёт также входят KV-кэш, рабочая область для вычислений и буфер предзагрузки. Больший контекст увеличивает KV-кэш, а при нехватке памяти можно уменьшить длину контекста или отключить предзагрузку.

Лимит задаётся явно через `--limit`, например `--limit=4GiB`. Это бюджет для планирования, а не гарантия производительности: скорость работы зависит от диска, устройства, архитектуры модели и будущего вычислительного бэкенда.

## Дорожная карта

1. Ускорить эталонный CPU-движок и подключить MLX/Metal на Apple silicon.
2. Добавить аппаратное ускорение на Linux и Windows.
3. Собирать **один автономный бинарный файл для Linux** и **один самостоятельный `AirLLM.exe` для Windows**.
4. Добавить подпись и нотаризацию готового автономного приложения `.app` для macOS.

Репозиторий содержит только Go-реализацию. Исторические Python- и Jupyter-файлы удалены из основной ветки и остаются доступны в истории Git.
